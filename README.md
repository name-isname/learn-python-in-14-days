# 14天学会Python编程

> 一条逐渐进阶的入门路线图：AI 能帮我们写代码，但无法代替我们理解程序。

以前学习编程很难，现在，AI 能极大地降低我们编程的困难。AI 能帮我们写代码，但是却无法帮助我们理解程序。不理解程序与计算机的原理，我们就无法更好地「许愿」；理解技术，才能更好地利用技术解决问题。有一些编程的基础，就可以去学习 AI，知道基本的配置是怎么回事了。

这份指南不是一份传统的教材，而是一份**目标清单**：传统的教学过于注重知识，忽略了实际问题和工程生态。我们需要紧盯问题，遇到什么问题就去学什么东西，同时紧跟社区的最佳工程实践，上来就以高标准来学习。

## 这份指南不是什么

- **不是 Python 语法课。** 指南不会详细讲解 Python 语法，这些内容唾手可得——菜鸟教程、Python 官方文档都可以查到，AI 更能提供针对性的教学。
- **不是科普文章。** 有科普的成分，但不会详细展开，只列出要学习的部分以及学习指引。
- **不会很庞大。** B 站上动辄数小时的 Python 课不够精要，很多东西学了用不上无异于浪费时间。我们只学习必要知识，遇到新问题再补充相关内容，做到凡是学的都用上。

## 学完你能做到

1. 学会使用命令行，能用命令行解决问题
2. 学会 Python 语法
3. 理解一个程序的后端是怎么写的
4. 理解 Web 应用和后端的关系
5. 掌握 Python 现阶段生态下的最佳实践

## 元方法：学会任何东西的能力

坦白说，这套内容入门程序员足够，解决生活问题绰绰有余，但对于应聘还远远不够。这份指南只能开个门，后面更难的路需要自己走——所以最需要掌握的，是**学会任何东西的能力**。以下方法适用于学习具体语言、学习包、学习工具：

1. **询问 AI**，无论什么问题。
2. **二八法则**：不要求把握一个方法 / 文档 / 工具的全部内容，只需要最常用的 20% 就够用了，剩下的用到时再学。
3. **找到知识源头**：官方文档而非二手解读。官方的 Document/Tutorial 通常有 Install / Quick Start 帮助快速上手，命令行工具通常也有 help 命令。
4. **减少难度**：如果一次学习的难度太高，就拆解成更小的部分，允许自己更慢地掌握，理解优先。

这些方法可以交叉配合，比如问 AI 了解 20% 的高频用法。

## 学习方法：总体要求

1. 体验完整流程
2. 要实操
3. 要理解过程

建立对一个东西整体性的理解很重要——理解它解决了什么问题。边学边干，用不断完成的小目标，积累起大成果。

### 关于可选和进阶

所有的可选和进阶都是有用的，只是初上手会增加阻力。对于立志让技术为己所用的人来说都是必学：可选内容往往是更好的解决方案、社区的最佳实践，比如包管理工具能极大改善装软件时的痛苦，学会它就能更高效地解决问题。
