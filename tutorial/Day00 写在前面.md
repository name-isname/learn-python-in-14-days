# 写在前面
以前学习编程很难的，现在，AI能极大地降低我们编程的困难。AI能帮我们写代码，但是却无法帮助我们理解程序，不理解程序与计算机的原理也让我们无法更好地许愿，理解技术才能更好地利用技术解决问题。有一些编程的基础，就可以去学习AI，能知道那些代码是怎么回事了。

这份指南不是什么？
- 不是python语法课。指南中不会详细讲解python语法，这些内容太简单也唾手可得，无论是菜鸟教程还是python官方document都可以查到。再者现在都AI已经足够强大，能够提供更针对性的教学。
- 不会很庞大。b站上动辄数小时的python课不够精要，很多东西学了用不上无异于浪费时间。我们先只学习必要知识，遇到新问题再补充相关知识，做到凡是学的都用上。

那么这份指南会有什么？
- 一条逐渐进阶的路线图，带你认识python生态。不同与专注于语法的课程，python真正厉害之处在于庞大的生态，能够解决各种问题。指南会从命令行开始，从uv到python语法，再认识python包，理解数据库和前端，写出一个自己的程序。
- 一份精要目标指导。指南会逐级提出一系列目标，基于这些目标去和AI交流学习，能够集中高效地学习编程。指南不仅包括内容也包括方法，在必要的时候也会给出指引帮助渡过困难的部分。
- 现代化。有些python的书/课太陈旧，已经脱离了社区最佳实践。指南会以社区的最佳实践为准，帮助大家更优雅地解决问题。

最后希望能带领大家做到：
1. 使用命令行，用命令行解决实际问题
2. 学会python语法
3. 理解一个程序的后端是怎么写的
4. 理解web应用和后端的关系
5. 掌握python现阶段生态下的最佳实践
而我觉得最需要学会掌握的，是学会一个东西的能力。坦白说上面这套入门程序员足够，解决生活问题绰绰有余，但对于应聘远远不够。有些东西指南不会讲，指南只能开个门，而后面更难的路需要自己走。掌握学会任何东西的能力后，就可以自己去学。

下面是学习的通用指导，你第一次看可能觉得没什么，不过当你遇到问题时，别忘记回来看看，按照方法去尝试能帮你解决不少问题。元方法（意为通用方法，可以用在学习任何具体语言/包/工具上）：
1. 询问AI，无论什么问题。
2. 不要求把握一个方法/文档/工具的全部内容，只需要最常用的20%就够用了，剩下的用到的时候再学习。
3. 找到知识源头（意指官方文档，而非别人的二手解读）。官方的Document/Tutorial通常会有Install/Quick Start/Start/Begin帮助快速上手，命令行工具除了文档通常也会有help命令。
4. 减少难度，如果一次学习的难度太高，就拆解成更小的部分，允许自己更慢地掌握，理解优先。
上面的方法可以交叉配合，比如问AI了解20%高频用法。

下面是学习的原则，按照这些学习原则来能够更高效地掌握编程。相比于传统的疯狂灌输式的学习，编程更在于实操和流程机制的理解。
1. 体验完整流程。完整流程很重要，只有真正整个流程跑通了一遍，才至少称得上成功了一次，在此基础上再去理解流程。
2. 要实操。编程不是记忆性的学习，而是感受这个工具，使用这个工具，把握它的能力边界。
3. 要理解机制。编程是完完全全的人造物，所有的东西都是由逻辑构筑起来的，这些都是可理解也正是编程的精髓，学会理解代码为什么是这样的。

关于可选和进阶的说明：所有的可选和进阶都是有用的，只是初上手会增加阻力，对于立志技术为己所用的人都是必学。可选都是更好的解决方案、社区的最佳实践，比如软件包管理工具能够极大改善下软件时的痛苦，学会能更高效地解决问题。

最后有一些鼓励的话。你可能真的对编程提起了兴趣，不过我还是想说，学好编程真的很难。
有些人可能生来就很害怕陌生的东西与错误，我就是如此。我相信肯定也有许多人在面对自己电脑上那些不知作用的文件夹时都会恐惧，我曾经也是如此。这份指南里，哪怕我已经减少了很多困难的部分，但依然会有很多你曾经没做过，害怕出错的事。
人在面对未知的事物时天然会恐惧会逃避。我也逃避过，曾经我逃避之后还是放不下，我一直想写出自己的软件。于是顶着恐惧，学了5天，最后没想到只花了1天就写出软件了。我想告诉你，害怕是正常的，想逃也是正常的，没有人不怕。还记得前面的元方法吗，在恐惧的时候停下来，去看看元方法，允许自己慢一点。

希望大家都能克服困难，学会技术，找到乐趣，解决问题。一句来自《纳瓦尔宝典》的话放到最后：“Easy choices, hard life. Hard choices, easy life. ”
