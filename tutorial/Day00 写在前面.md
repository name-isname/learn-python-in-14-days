# 写在前面
以前学习编程很难的，现在，AI能极大地降低我们编程的困难。AI能帮我们写代码，但是却无法帮助我们理解程序，不理解程序与计算机的原理也让我们无法更好地许愿，理解技术才能更好地利用技术解决问题。有一些编程的基础，就可以去学习AI，知道基本的配置是怎么回事了。

这份指南不是什么？
- 不是python语法课。指南中不会详细讲解python语法，这些内容太简单也唾手可得，无论是菜鸟教程还是python官方document都可以查到。再者现在都AI已经足够强大，能够提供更针对性的教学。
- 不是科普文章。有科普的成分，但是和python一样不会详细说明内容，而是只会列出要学习的部分以及学习指引，再者AI很好用。
- 不会很庞大。b站上动辄数小时的python课不够精要，很多东西学了用不上无异于浪费时间。我们先只学习必要知识，遇到新问题再补充相关知识，做到凡是学的都用上。

那么这份指南会有什么？
- 一条逐渐进阶的路线图。
而是一份目标清单，现在的AI已经足够强，能代替教学，传统的教学过于注重知识，忽略了实际问题/工程生态，现在需要紧盯问题，遇到什么问题就去学什么东西，同时紧跟社区的最佳工程实践，上来就是以高标准来学习。

最后能带领大家能做到
1. 学会使用命令行，能用命令行解决问题
2. 学会python语法
3. 理解一个程序的后端是怎么写的
4. web应用和后端的关系
5. 掌握python现阶段生态下的最佳实践

我觉得最需要学会掌握的，是学会一个东西的能力。坦白说上面这套入门程序员足够，解决点生活问题绰绰有余，但对于应聘远远不够，笔试都过不了。这个指南在这里结束了，但学习没有结束，指南只能开个门，而后面更难的路需要自己去走，所以掌握学会任何东西的能力很重要，后面的就需要自己去学了。

元方法（意为通用方法，可以用在学习具体语言，学习包，学习工具上）：
1. 询问AI，无论什么问题。
2. 不要求把握一个方法/文档/工具的全部内容，只需要最常用的20%就够用了，剩下的用到的时候再学习。
3. 找到知识源头（意指官方文档，而非别人的二手解读）。官方的Document/Tutorial通常会有Install/Quick Start/Start/Begin帮助快速上手，命令行工具除了文档通常也会有help命令。
4. 减少难度，如果一次学习的难度太高，就拆解成更小的部分，允许自己更慢地掌握，理解优先。
上面的方法可以交叉配合，比如问AI了解20%高频用法。

学习方法，总体要求
1. 体验完整流程
2. 要实操
3. 要理解过程
建立对一个东西整体性的理解，理解一个东西解决了什么问题很重要
边学边干，用不断地完成小目标，积累起大成果。

关于可选和进阶的说明：所有的可选和进阶都是有用的，只是初上手会增加阻力，对于立志技术为己所用的人都是必学。可选都是更好的解决方案、社区的最佳实践，比如软件包管理工具能够极大改善下软件时的痛苦，学会能更高效地解决问题。
